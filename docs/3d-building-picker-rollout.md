# A1 동 선택 3D 교체와 복구

기존 위저드의 첫 동 선택 영역에서 3D 모형을 바로 불러온다. 준비되는 동안에도 기존 카드는 렌더링하지 않는다. 지도나 데스크톱 오른쪽의 작은 동 목록에서 선택하면 건물 외곽에만 민트색 윤곽선이 나타나고, `NNN동 세대 선택`을 눌러 기존 세대 화면으로 간다. 공유 열람 인증의 동 선택과 세대·닉네임 단계는 기존과 같다.

- 즉시 카드로 들어가는 주소: [기존 카드로 동 선택](https://is2js.github.io/naksaeng/bunfirvil/?buildingPicker=cards). 쿼리가 있는 동안 3D 모듈을 요청하지 않으며 저장·인증 규칙은 그대로다. WebGL/WASM 또는 모델 로드에 실패해도 자동 전환하지 않는다. 오류 화면에서 `다시 불러오기` 또는 `기존 카드로 선택`을 직접 고를 수 있다.
- 서버/저장 키, 세대 카탈로그, 정적 경로는 변경하지 않는다. `#building=105`처럼 유효한 세대 단계 딥링크는 3D를 로드하지 않는다.
- 교체 전 운영 소스: [GitHub 백업 태그](https://github.com/is2js/naksaeng/tree/bunfirvil-before-3d-picker-2026-11-23), 커밋 `178946d73c6850f45f2fc77c3960ab6618b24941`. 이 버전을 올린 [Pages 실행 기록](https://github.com/is2js/naksaeng/actions/runs/44443101467)도 보존되어 있다.
- 제품 기본값 전체를 복구하려면 `git revert`로 3D 선택 화면의 후속 변경을 최신순으로 되돌린 뒤 도입 커밋 `d3c714e`를 되돌리고 `main`을 푸시한다. 이후 커밋을 삭제하는 reset/강제 푸시는 필요 없다. Pages 성공 후 일반 루트의 카드, 직접 링크, 모바일 세대 선택을 확인한다.

## 단지 시설 범례

단지배치도 PDF 4쪽 왼쪽 상단의 실제 표기를 기존 북향 좌표계에 옮겼다. 모든 시설이 선택 가능한 아파트 동을 뜻하는 것은 아니다. 도면과 다른 모델 표고가 있으면 해당 모델의 지면·테라스·지붕을 따라 표시하고, B1 시설은 타워 지붕이 아닌 도면의 지상 위치를 가리킨다. 빨간 오각형은 주거용 쓰레기 분리수거장만 의미한다(청록색 오각형의 근린생활시설 분리수거장은 제외).

지하출입계단과 분리수거장 기호는 해당 지점의 보행로·테라스 표면 위에, 넓은 반투명 시설 표시보다 나중에 그린다. 건물에 가려지는 경우에는 기존처럼 그 뒤에 숨는다.

`시설 범례` 필터는 현재 숨기며 지도 위 시설 표시 자체는 유지한다. 전체 보기에는 주·부출입구와 클릭 가능한 커뮤니티센터 Ⅰ·Ⅱ 및 어린이집 이름을 표시한다. 나머지 시설은 기호를 유지하고 145%부터 이름을 표시한다. 시설 글씨는 동 번호보다 작고, 상세가 있는 세 시설에만 작은 버튼 배경을 사용한다. PC에서 왼쪽 드래그는 회전, 오른쪽 드래그는 화면 이동이다. 지도 위에서는 브라우저 우클릭 메뉴가 열리지 않으며, 초기화는 `다시 한눈에` 버튼으로 한다.

어린이집 지붕은 노란색 반투명 면, 커뮤니티센터 1·2는 PDF에 그려진 B1 구역의 지상 범위를 따라 빨간색 반투명 면으로 표시한다. 커뮤니티센터 외형은 도면 4쪽의 경계와 투시도, 6쪽 조감도를 따라 유리·석재 입면과 연속 옥상을 보정한다. 커뮤니티센터 1의 놀이터 쪽 정면은 모델하우스 사진을 참고해 밝은 석재 기둥, 어두운 창, 외부 승강기 탑, 식재 옥상과 목재 데크를 표현한다. 단차를 직접 잇는 새 계단은 추가하지 않는다. 상단지 가운데 부출입구와 105동 옆 지하차도는 유지한다.

어린이집은 도면 4·5·6쪽과 모델하우스 사진을 대조해 건물 방향을 유지하고, 동쪽 유아놀이터를 마주 보는 짧은 벽 가운데에 작은 박공 현관을 배치한다. 같은 면을 따라 낮은 포치를 두고 유아놀이터 보행로 및 1층 중앙 복도와 연결한다. 3D 단지의 외관과 실내 1·2층은 같은 방위를 사용한다. 포치와 연결로의 세부 치수는 모형용 추정치다.

어린이집 외부의 유아놀이터는 4쪽 북향 배치도에 맞춰 104·105동 사이 포치 앞의 초록 포장으로 옮겼다. 길은 놀이터를 관통하지 않고 둘레에서 단지 경계 보행로와 105동 쪽 주 보행로에 합류한다. 6쪽 조감도와 플라이오버를 대조해 낮은 관목, 꽃나무 띠, 녹색 지붕과 주황 미끄럼틀을 표현하되, 수종·수량과 길 너비는 모형용 추정값이다.

윗단지는 4쪽 상세 도면과 사선 모형을 참조해 110동 쪽 주출입구와 109동 쪽 부출입구에서 각각 지하주차장으로 내려가는 형태를 표현한다. 110동은 주차 입구 지붕에서 드포엠플레이까지 평평한 상부를 만들고, 외부 승강기는 아래 진입층과 위쪽 키즈스테이션·놀이터 사이를 연결하는 위치에 둔다. 109동은 램프 지붕과 미스티포레를 같은 상부에 두고 도로 쪽 단차를 석재 기단으로 표현한다. 두 곳 모두 노출된 경사 차로는 열어 둔다. 105·109동 경비실과 지붕 위 민트 표시를 두 단지 사이 경계선과 평행하게 맞췄다. 111·112동 뒤편 출입부는 외곽 보행로에 연결한다. 두 단지 사이 공원은 양쪽 지면 높이와 잔디색을 이어 주되 기존 보행로로 경계를 남기고 강 쪽 대지 마진을 넘지 않는다. 어린이집 2층의 바깥 테라스에는 낮은 난간을 둔다. 곡률·경사·너비는 배치도 비례를 옮긴 모형 값이다.

106동 앞에서 커뮤니티센터 Ⅰ 상부와 105동 앞을 거쳐 단지 사이 공원 쪽까지 이어지는 띠 포장 보행로에 붉은 반투명 범위가 끊기지 않고 겹쳐 보이게 했다. 커뮤니티센터 외곽을 바꾸거나 아래 놀이터와 직접 잇는 계단을 추가하지 않는다. 드포엠카페는 긴 축의 박공 유리면을 분수 쪽으로 향하게 하고, 어린이집·드포엠파크·드포엠플레이의 외형은 6쪽 조감도를 참조했다. 101동 근린생활시설은 분리된 박스 대신 타워 하부에 붙는 상가 기단으로 표현한다.

101·108동 사이 정문에서는 키즈스테이션을 주출입구 서쪽의 대기 공간에 두고, 외부 승강기 표시는 더 안쪽 주차장 진입부 옆 승강기와 맞췄다. 105동 앞과 중앙공원의 보행로는 겹치던 포장을 걷어내고 주 보행로와 공원 산책로를 구분한다. 단지 사이 공원의 서쪽 끝은 두 대지의 수변 경계 안쪽에서 정리하고, 커뮤니티센터 Ⅱ와 인접 근린시설은 낮은 쪽 보행로에서 석재·유리 입면이 읽히도록 단차를 맞췄다. 보행로는 기존 중복 포장을 제거하고 북서쪽에서 남쪽 모서리를 돌아 동쪽으로 잇는 단일 외곽 노선을 사용한다.

서쪽 수변에서는 도면의 어두운 대지 바깥 표현을 높이차로 읽지 않는다. 두 단지의 물 쪽 수직 대지면만 제거하고, 각 구간의 기존 단지 표고에서 같은 높이의 녹지와 얕은 물길로 이어지게 했다. 흙의 단차 대신 수목 띠가 대지와 강둑을 구분한다. 단지 동쪽의 도로·출입구와 커뮤니티 기단은 이 보정 대상에 포함하지 않는다.

커뮤니티센터 Ⅰ·Ⅱ와 어린이집의 이름이나 지도 위 반투명 영역을 누르면 해당 위치로 확대하면서 같은 지도 영역 안에서 5쪽 컷어웨이 기반 3D 단면으로 전환한다. 어린이집 진입 전환에서는 104동만 잠깐 반투명하게 보인다. 두 센터는 층 표시 없이 각각 단층으로 열리고, 어린이집은 모형 안의 계단 버튼으로 1·2층을 오간다. 기본 시점에서 방 이름을 볼 수 있고, 모형의 방을 누르면 용도를 확인한다. 다함께돌봄센터는 실제 내부 구획을 보존하고 이름과 선택 상태는 하나로 표시한다. `단지로 이동` 또는 Esc로 돌아오면 해당 시설 앞의 확대 시점과 선택한 동이 유지된다. 이후 직접 지도를 조정하거나 `다시 한눈에`로 전체 보기를 열 수 있다. 캐릭터 조작은 없으며, 축척·세부 치수와 단면의 추정 부분은 시공용이 아니다. 최초 단지 화면에서는 상세 뷰어를 불러오지 않고, 원본 PDF·사진·GLB는 교체하지 않는다.

## 공개 자산

공개 파일은 로컬에서 자체 제작한 `src/site-preview/assets/bunfirvil-site-v9.glb` 한 벌(731,620바이트, 49,227 삼각형)과 Three.js의 로컬 WASM 디코더다. 첨부 단지배치도와 모형 사진은 배치의 참고이며 PDF·사진 원본·Blender 편집 원본·로컬 시안 페이지는 배포하지 않는다. 장면은 시공 치수나 정확한 고도를 보장하지 않는다. `scripts/verify-dist.mjs`가 승인된 GLB 해시, 단지 모형/디코더 1.2 MiB, 나머지 앱 50 MiB, 전체 100 MiB 한도를 확인한다.
