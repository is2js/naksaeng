# 55B 다용도실 문·설비벽 연속 접속 보정

## 원인

이전 보정은 800mm 문 옆에 190mm 길이의 짧은 벽만 추가했다. 이 벽은 전고 2.3m였지만, `apartmentSolidBlockVisualFootprint()`의 기존 접촉 여유 처리에서 설비벽과 끝점만 맞닿아도 설비벽 동측 전체를 잘라냈다.

- 설비벽 동측 면: X3.55 → X3.335, 215mm 누락
- 남측 외벽 접속: Y9.10 → Y9.085, 15mm 틈
- 화면과 레이저는 절삭된 footprint를 사용하지만 이동 mask는 원래 bounds를 사용해 서로 불일치했다.

이는 문 상인방의 높이 오류가 아니라 **짧은 벽과 넓은 설비벽의 면 소유가 불완전한 문제**였다. 공통 절삭 함수를 모든 평형에서 바꾸지 않고 55B 정본의 접속만 바로잡는다.

## 수정

- `utility-kitchen-east-after`: X3.45, Y8.06부터 외벽 접점 Y9.20까지 하나의 200mm 연속 벽으로 구성한다.
- `utility-solid-column`: 동측 끝을 X3.35로 분리해 연속 벽의 서측 면에 정확히 맞닿게 한다. 이 핵심부만 `wallContactClearanceMeters: 0`으로 명시한다.
- 설비벽+벽이 차지하는 실내 영역의 합집합은 원래 raw geometry와 같다. 같은 부피를 이중 소유하거나 215mm 빈 면을 남기지 않는다. 외벽과 만나는 모서리는 기존 일반 벽 접속 방식대로 닫는다.
- 문 개구부 `[3.45,7.26]–[3.45,8.06]`, 800mm 통행 폭·문짝 위치·열림 상태는 유지한다.
- 문 반대편의 주방 열린 경계와 기존 다용도실 북측 벽·아일랜드 앵커, 바닥 타일도 이동하지 않는다.
- A–D 변환 전에 같은 로컬 정본을 한 번 적용한다. 모든 평형의 파란 치수 46개와 저장 가구 좌표는 변경하지 않는다.

벽·설비벽의 정상적인 시선별 가림은 유지한다. 가려지지 않은 설비벽까지 강제로 반투명화하는 그룹 예외는 추가하지 않는다. 길이·벽 두께는 기존 가상 모델과 사용자 사진/설명에 기반한 값이며 실제 시공 확정 치수가 아니다.

## 최소 확인

- A–D에서 문 양방향 통행 및 벽 본체 통과 차단
- 문 옆/설비벽 구간 Y8.15·8.50·8.90의 실제 Three.js mesh와 레이저가 같은 X3.55 면에서 만나는지 확인
- 설비벽 실제 footprint가 X3.35/Y9.10에서 틈 없이 끝나는지 확인
- 전 평형 46개 치수, 기존 55B 기하·통행 및 서비스 타일 관련 검사
- 1440px A/B 및 390px A의 전후 화면·가로 넘침·JS 오류 확인
- production build와 정적 배포 검사. PVP 원본·생성 snapshot·가격·인증·저장 키는 수정하지 않는다.
